# dongsoo-eunji.github.io

## 베스트샷 갤러리

`/wedding/`과 `/wedding/m/`은 공통 `PhotoEvent` 컴포넌트에서 베스트샷을 표시합니다.
사진 응모 접수는 종료되었으며, 접수 폼과 시간별 접수·발표 화면은 제거했습니다.
갤러리는 배포 직후 표시되며 사진 목록은 나중에도 수정할 수 있습니다.

공개 베스트샷은 DB 결과 API 대신 `source_images/베스트샷` 폴더에서 준비합니다.
사진을 추가·교체·삭제한 뒤 `pnpm best-shots:prepare`를 실행하면
`static/wedding/images/best-shots`에 긴 변 최대 1920px의 WebP와 400×400 정사각
썸네일, `gallery.json` 목록이 생성됩니다. 큰 사진은 원본 비율을 유지하며 작은
원본을 확대하지 않습니다. 사진 수에 제한이 없습니다.
동일한 원본 파일은 한 장으로 처리합니다. 공개 파일명은 원본 내용의 해시를 사용해
이름·연락처를 노출하지 않고, 교체된 사진의 URL도 함께 바뀝니다.

표시 순서는 `scripts/best-shots-order.json`의 이미지 ID 순서를 따릅니다.
최종 5장은 기존 순서를 기준으로 3, 5, 1, 4, 2 순서이며 재변환해도 유지됩니다.
순서 목록에 없는 새 사진은 원본 파일명 순서로 마지막에 추가됩니다.

변환 명령은 다시 실행할 수 있으며 목록에서 빠진 사진의 생성 파일도 정리합니다.
원본은 그대로 보존합니다. FFmpeg가 필요하고, `FFMPEG_PATH`로 실행 경로를 지정할
수 있습니다. `pnpm dev`와 `pnpm build`도 원본 폴더가 있으면 자동 변환합니다.
원본 폴더는 Git에서 제외되므로 생성된 WebP와 JSON을 함께 커밋해야 합니다.
CI에서는 원본 폴더가 없으면 커밋된 결과물을 그대로 배포합니다.

두 청첩장 모두 이름 없이 베스트샷 전체를 표시하고, 공통 갤러리의
썸네일·확대 보기와 좌우 넘기기를 사용합니다. 안내 문구는
“응모해 주셔서 감사합니다. 선정되신 다섯 분께는 10월 5일 연락드리겠습니다. 감사합니다.”입니다.
변환·재실행 테스트는 `pnpm best-shots:test`로 실행합니다.

공개 방명록은 이름과 내용만 표시하며 작성 시각은 노출하지 않습니다. 작성 시각은
운영 기록을 위해 API 서버 DB와 인증된 관리자 화면에만 유지됩니다.

기존 응모 API의 운영·종료 설정은 서버의
`/home/letrhee/docker_compose_script/wedding_api/README.md`를 참고하세요.

## 청첩장 잠금

표시합니다. 현재 `.env`의 `see_passwd`에서 한 번 생성한 random salt와
PBKDF2-SHA256 결과만 코드에 포함하며 원문 비밀번호나 Actions secret은 사용하지
않습니다. 경계 및 해시 테스트는 `pnpm access:test`로 실행합니다.
